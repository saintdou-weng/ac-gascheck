# 清潔人員、廚房與垃圾桶清冊更新（2026-11-28）

## 操作

- 清潔管理 → **人員與分工**：原本設定中的清潔員、檢查員已移到同一分頁，不用再建立第二份名單。
- 點地點的 **人員列表**，或新增紀錄中地點旁的 👥，看負責人、工號、照片與所選日期的出勤。照片沿用該裝置 PSJHR 已有的員工照片。
- **組織／工作分配圖**：上方顯示原檢查員，下方依清潔地點顯示負責人。這是工作分配關係，沒有推定或修改 HR 的主管職位。
- 完整姓名或工號只有唯一對應時才自動連結。簡稱、拼字差異、同名者可按人員的「查看」，搜尋後指定正確工號。
- **更新人員／出勤** 是一次讀取；本次開啟已讀取的人員、出勤批次會快取，不定時輪詢。初次優先讀取同一裝置的 PSJHR；沒有本機資料時才讀雲端。查不到日期資料標示「出勤未取得」，無刷卡列標示「無刷卡紀錄」，均不自行判定缺勤。
- **廚房**為獨立檢查地點，與飯堂分開；預設跟隨 PSJHR 廚房／廚師編制，可改為手動多人分配。原檢查員與原紀錄不變。預設清潔員「套用全部」會保留廚房編制。
- 已存在的廚房不重複新增；刪除廚房後不會每次開啟又自動補回。
- **垃圾桶地圖**：各種類使用桶、籃、有蓋桶、推車圖示；下方可搜尋的清冊與地圖讀同一份區域數量，點選可編輯。原「個別登記」保留為明細，不把它與區域數量重複相加。

## 資料與部署

新增 `gc-cleaning-team.js`、`gc-cleaning-team.css`，並更新 `ac_gascheck_cleaning_v2.html`。三個檔案需一起上傳到原 GitHub 倉庫根目錄。保留其餘原檔案。

**不需修改或重新部署 Apps Script。** 工號連結、區域分配透過原 Cleaning 設定同步；PSJHR／出勤只讀取，不寫入或複製 HR 主資料至 Cleaning 雲端設定。不變更 Telegram Bot、群組或核可流程。

設定優先沿用已儲存的區域分配。舊預設責任人若已不在清潔員名單，顯示該區最近一日的實際清潔紀錄人員，並標示來源；不改寫舊紀錄。
